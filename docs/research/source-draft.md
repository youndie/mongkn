# Project Context & Goal
You are an expert Kotlin Multiplatform and C-interop developer. Your task is to build an MVP of a Kotlin/Native wrapper around the official MongoDB C Driver (`libmongoc`). 
The ultimate goal is to generate the API surface using KSP + KotlinPoet to mirror the official `kotlin-mongo-coroutines-driver`, but for this MVP, we will limit the scope to a strictly defined subset.

**Target Platform:** `macosArm64` (Apple Silicon) or `linuxX64`. 
**Key Technologies:** Kotlin/Native, `cinterop`, `kotlinx.coroutines`, KSP (Kotlin Symbol Processing), KotlinPoet.

## Core Rules for the Agent
1. **Memory Management is Critical:** Always use `memScoped`, `Arena`, or explicit `_destroy()` functions when interacting with C-pointers. Avoid memory leaks at all costs.
2. **Coroutines bridging:** All C-driver network calls must be wrapped in `suspend` functions and dispatched to a background thread pool (e.g., `Dispatchers.Default`) so they do not block the main thread.
3. **No JVM dependencies:** This is a pure Kotlin/Native (or KMP) module. You cannot use `java.*` or `org.bson.*` classes.

---

## Phase 1: Environment & C-Interop Setup
**Goal:** Successfully link `libmongoc` and compile a "Hello World" native executable.

1. **System Dependencies:** Instruct the user to install the C driver (e.g., `brew install mongo-c-driver` on macOS).
2. **Gradle Setup:** 
   - Create a Kotlin Multiplatform project.
   - Configure the `macosArm64` target.
   - Setup `cinterop` block in `build.gradle.kts`.
3. **The `.def` file:** 
   - Create `src/nativeInterop/cinterop/mongoc.def`.
   - Configure headers (`mongoc.h`, `bson.h`).
   - Configure linkerOpts (`-lmongoc-1.0`, `-lbson-1.0` and paths to brew installation, typically `/opt/homebrew/lib` and `/opt/homebrew/include`).
4. **Validation:** Write a `main()` function that calls `mongoc_init()` and `mongoc_cleanup()`. Ensure the project compiles and runs without linker errors.

---

## Phase 2: BSON Mapping Layer
**Goal:** Convert between native C BSON structures and Kotlin objects without memory leaks.

1. **Kotlin Document:** Create a simple KMP `Document` class (e.g., a typealias or wrapper around `Map<String, Any>`).
2. **Kotlin to C (`bson_t`):** 
   - Write an extension function: `fun Document.toNativeBson(scope: MemScope): CPointer<bson_t>`
   - Support mapping basic types: `String`, `Int`, `Double`, `Boolean`, and nested `Document`.
   - Use `bson_new()`, `bson_append_utf8()`, etc.
3. **C (`bson_t`) to Kotlin:**
   - Write an extension function: `fun CPointer<bson_t>.toKmpDocument(): Document`
   - Iterate over the C structure using `bson_iter_t`.
4. **Validation:** Write a unit test that takes a Kotlin `Document`, converts it to `bson_t`, converts it back to Kotlin, and asserts equality.

---

## Phase 3: Core Mongo Wrappers (Manual PoC)
**Goal:** Implement the minimal wrapper classes manually to validate the architecture before writing the KSP generator.

1. **Initialization:**
   - Implement `MongoClient` wrapper (holds `mongoc_client_t`).
   - Implement `MongoDatabase` wrapper.
   - Implement `MongoCollection` wrapper.
2. **Implement `insertOne`:**
   - Signature: `suspend fun insertOne(document: Document): Boolean`
   - Wrap the call in `withContext(Dispatchers.Default)`.
   - Convert `Document` to `bson_t` using `memScoped`.
   - Call `mongoc_collection_insert_one`.
   - Read `bson_error_t` and throw a custom `MongoException` if it fails.
3. **Implement `find` (Cursors & Flow):**
   - Signature: `fun find(filter: Document): Flow<Document>`
   - Call `mongoc_collection_find_with_opts`.
   - Return a `flow { ... }` that iterates using `mongoc_cursor_next`.
   - **CRITICAL:** Ensure `mongoc_cursor_destroy` is called in a `finally` block within the Flow to prevent leaks if the Flow collection is cancelled.
4. **Validation:** Write an integration test connecting to a local MongoDB instance. Insert a document, read it back via Flow, and assert correctness.

---

## Phase 4: KSP Generator (The final MVP step)
**Goal:** Replace the manual `insertOne` and `find` implementations in `MongoCollection` with code generated by KSP.

1. **Module Setup:** 
   - Create a separate JVM module for the KSP processor.
   - Add dependencies: `symbol-processing-api`, `kotlinpoet`, `kotlinpoet-ksp`.
   - Add the official JVM driver `com.mongodb.kotlin.client.coroutine.MongoCollection` as a `compileOnly` dependency so KSP can resolve its symbols.
2. **Processor Logic:**
   - Create `MongoApiGeneratorProcessor`.
   - Look up the official `MongoCollection` using `resolver.getClassDeclarationByName()`.
   - Filter for `insertOne` and `find` methods.
3. **Code Generation:**
   - Use KotlinPoet to generate `NativeMongoCollection` interface.
   - Use KotlinPoet to generate `MongoCollectionImpl` class.
   - Inject the C-interop logic (from Phase 3) into the generated method bodies using String templates and KotlinPoet's `%M` (MemberName) for `cinterop` and `coroutines` functions.
4. **Validation:** Hook the KSP processor into the main Native module. Delete the manual `MongoCollection` code. Compile the project and ensure the integration tests from Phase 3 still pass using the auto-generated code.
