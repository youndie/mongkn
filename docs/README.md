# docs — документация mongkn

`mongkn` — обвязка MongoDB для Kotlin/Native поверх официального C-драйвера (`libmongoc`).
Документация разложена по слоям: от «что и зачем» к «как это устроено на проводе» и «как
эксплуатируется».

```
[ Research (почему так; что проверено, что гипотеза) ]
            │
[ Feature (что даёт пользователю + BDD) ]
            │
[ API (публичная поверхность библиотеки) ]
            │
[ Service (модуль: владение, сборка, грабли) ]
```

| Слой | Папка | Отвечает на вопрос |
|---|---|---|
| Research | `research/` | почему архитектура именно такая; что проверено, что гипотеза |
| Feature | `features/` | что делает библиотека и зачем, BDD-сценарии = критерии приёмки |
| API | `api/` | публичная поверхность: сигнатуры, ошибки, отличия от официального драйвера |
| Service | `services/` | зона ответственности модуля, сборка, грабли |

Слоя `screens/` нет: клиента у библиотеки нет.
Слой `api/` здесь — не HTTP, а публичный Kotlin-API; ничего «на проводе» mongkn не определяет,
протокол принадлежит MongoDB.

## Оговорка про статус

Инвариант: **`main` описывает то, что есть.** Сегодня реализована только веха M0 —
`cinterop`, инициализация драйвера и тип ошибки. Всё остальное в
[api-collection](api/api-collection.md) и [feature-crud-mvp](features/feature-crud-mvp.md)
помечено как **целевое** и живёт там как контракт, который ещё предстоит реализовать.

Отдельно: в ресёрче отделены **прогоны** (скомпилировано и запущено) от **чтения заголовков**
и от **гипотез**. Если правите утверждение — перепроверяйте источник, а не соседний документ.

## Соглашения

- `id` во frontmatter = имя файла.
- **Главный потребитель — Claude Code.** Каждый документ даёт якоря кода: путь к файлу, а не
  пересказ его содержимого. Путь остаётся верным, копия протухает.
- Один документ = одна сущность.
- Числа, коды ошибок и тексты в BDD — только проверенные прогоном; выведенные из чтения
  заголовков помечены отдельно и подлежат сверке при реализации.
- Гипотезы называются гипотезами.
- Язык — русский; идентификаторы C и Kotlin, имена задач Gradle — вербатим как в коде.
